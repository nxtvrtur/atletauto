# Конвейер статей блога

Статьи не пишутся руками и не вставляются в вёрстку руками. Есть план тем,
дедуп против сайта партнёра и сборка страниц из шаблона.

## Как выпустить очередную порцию

```bash
node blog-gen/next-batch.mjs --stats     # что сделано, что осталось
node blog-gen/next-batch.mjs 25 > /tmp/batch.json
```

Дальше `/tmp/batch.json` отдаётся генератору (Claude Code, воркфлоу
`atletauto-blog-nocompete` — он написан под этот формат тем), результат
складывается в `articles.json` и собирается:

```bash
python3 blog-gen/qa.py articles.json        # брак не пускаем на сайт
python3 blog-gen/assemble.py articles.json  # страницы + индекс + sitemap
git add blog/ blog.html sitemap.xml && git commit && git push
node indexnow.mjs <новые-url>               # сказать Яндексу и Bing
```

`assemble.py` пересобирает индекс блога с нуля из `blog-index-base.html`,
поэтому удаление статьи не оставляет висячую карточку.

## Два правила, ради которых всё это

**1. Не отнимать трафик у витрины-партнёра.** У importdare помодельные
страницы «растаможка <модель>» — её основной трафик (71% кликов), и по
«растаможка zeekr 001» её страница стоит на третьей позиции. Мы туда не лезем.
Дедуп в `next-batch.mjs` сверяет каждую тему со списком её статей
(`importdare-slugs.txt`) и отдельно режет всё, где в слаге есть название модели.

Список слагов витрины обновлять при заметных изменениях у неё:

```bash
ls "../DARE/importdare-site/content/blog/" | sed 's/\.html$//' > blog-gen/importdare-slugs.txt
```

**2. Не плодить тонкий контент.** У витрины есть раздел из 379 сгенерированных
обзоров, который дал 7 показов и ноль кликов — их сделали по списку моделей, а
не по спросу, и робот потратил на них обход впустую. Поэтому тема попадает в
план, только если про неё есть что сказать по существу: конкретный маршрут со
своим плечом и сезонностью, конкретная процедура, конкретный вопрос партнёра.

## Про объём

Честный потолок этого плана — **около 140 тем**, и это не лень, а границы ниши.
Наша земля — Владивосток, логистика по России, приёмка, эксплуатация и работа
с партнёрами. Всё остальное либо уже занято витриной, либо будет тем самым
тонким контентом.

Расширять план можно, но только по данным: после того как первая сотня
отстоится в поиске месяц-полтора, смотреть в Вебмастере, какие темы собрали
показы, и достраивать план вокруг них. Наращивать вслепую до тысячи страниц —
ровно та ошибка, которая уже стоила витрине 379 пустых страниц.

## Файлы

- `topics.mjs` — план тем: города доставки, логистика, эксплуатация, партнёрам
- `next-batch.mjs` — очередь: минус написанное, минус пересечения, минус модели
- `importdare-slugs.txt` — слепок статей витрины для дедупа
- `qa.py` — проверка до сборки: объём, meta, обязательные блоки, ссылки, суммы
- `assemble.py` — сборка страниц из шаблона + индекс + sitemap
- `shell.tpl`, `blog-index-base.html` — шаблоны вёрстки
